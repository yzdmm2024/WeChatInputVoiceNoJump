# 微信输入法 3.5.3（微信内语音免跳转）静态分析报告

> 分析对象：`微信输入法-3.5.3.ipa`（TrollStore 侧载包）
> 主 Bundle：`com.tencent.wetype`（微信输入法 / WeType），版本 3.5.3 (736)
> 结论：所谓“微信内语音免跳转”，本质是把**录音 → 识别 → 回填文字**整条链路放进“被微信宿主托管的扩展进程”里完成，而不是旧逻辑那样用 `openURL` 唤起 `wxkb.app` 主程序。UI 面板用 iOS **Live Activity / 灵动岛 Widget** 渲染在微信之上。

---

## 1. 包内结构（提取自 IPA）

| 组件 | Bundle ID | 扩展点 | 说明 |
|---|---|---|---|
| 主程序 `wxkb.app` | `com.tencent.wetype` | — | 微信输入法主体（含 `WBVoiceInputLiveActivityManager`） |
| `WBVoiceInputWidgetExtension.appex` | `com.tencent.wetype.liveActivity` | `com.apple.widgetkit-extension` | **语音输入 Live Activity Widget 扩展**，最低 iOS 16.1 |
| `WXKBShareExtension.appex` | `com.tencent.wetype.shareExtension` | `com.apple.share-services` | 隔空传送 / 分享扩展 |

附带私有框架：`wcwss`(com.tencent.wcwss)、`WXP2PTransferDyn`(com.tencent.WXP2PTransferDyn) —— 均为**微信内部框架**，说明 WeType 与微信有同厂深层集成。

---

## 2. “免跳转”的开关字面证据（来自二进制字符串）

- `WtAppActionOpenVoiceNoRedirectionWechat` —— 开启“微信内语音免跳转”
- `WtAppActionCloseVoiceNoRedirectionWechat` —— 关闭
- `WtAppActionClickVoiceNoRedirection` —— 点击免跳转开关
- `voiceNoRedirectionWechatButton` / `setVoiceNoRedirectionWechatButton:` —— 微信内的“免跳转”按钮
- `WtAppSceneSubpageVoiceNoRedirection` / `WtAppSceneSubpageVoiceNoRedirectionFloating` —— 设置子页（普通 / 浮窗两种）
- `VoiceInputSceneWechatMicrophone` / `isInvokeWechatMicro` —— 微信麦克风语音场景

## 3. 旧“跳转”逻辑仍在（作为对照）

主程序 `wxkb` 中保留：
- `-[AppDelegate handleVoiceRecordOpenURL:]`、`-[AppDelegate updateOpenURLStateWithURL:]`
- URL Scheme `wetype://`（如 `wetype://feedback?...`）

这说明**默认/旧行为是：点麦克风 → `openURL` 拉起主 app `wxkb.app` 录音 → 再回填**，这就是“跳转”。

## 4. 录音→识别→回填链路（免跳转路径）

- **录音**：`WBAudioSessionScene`（`AVAudioSessionCategoryRecord` / `PlayAndRecord`）、`MicrophonePopWindowClick`、主 app 声明 `NSMicrophoneUsageDescription` + `UIBackgroundModes=audio`
- **识别（联网）**：`WBVoiceAudioUploadRequest`、`ImeVoiceRecognizeRequest/Response`、`WBVoiceInputAsrResultChannelDelegate`（腾讯 ASR）
- **回填文字**：`insertText:` / `insertTextDocument:` / `batchInsertTextDocument:`（键盘扩展 `textDocumentProxy` 写入微信输入框）

## 5. Live Activity 驱动

- 主程序 `wxkb/Logic/VoiceInput/WBVoiceInputLiveActivityManager.swift`：用 **ActivityKit**（`ActivityKit.activities.request/update/end`、`pushType`）请求/更新/结束实时活动
- Widget 扩展渲染 Dynamic Island 的 expanded/compact/minimal 区域（`isDynamicIslandDevice`），启动参数 `liveActivity?source=voiceInput`
- 因此“录音中”的富面板是**系统级浮层**（灵动岛 / 实时活动），直接盖在微信上，无需打开 app

---

## 6. 结论：为什么“不跳 app”

1. 微信里用的是微信输入法的**自定义键盘扩展**，扩展进程本身就由微信宿主托管，UI 直接画在微信输入框上方。
2. 点麦克风时，**免跳转模式不调用 `openURL` 拉起 `wxkb.app`**，而是：
   - 由键盘扩展 / `WBVoiceInputWidgetExtension` 直接录音（扩展持有麦克风 + audio 后台权限）
   - 音频经 `WBVoiceAudioUploadRequest` 上传腾讯 ASR
   - 识别结果用 `textDocumentProxy.insertText` 直接写回微信输入框
3. “录音中”面板由 **Live Activity / 灵动岛 Widget**（`com.tencent.wetype.liveActivity`）渲染，是浮在微信之上的系统 UI，不启动主程序。

## 7. 两点提醒

- **本 IPA 内没有 `com.apple.keyboard-service` 的键盘 .appex**（只有语音 Widget + 分享扩展），键盘逻辑在共享库 `WXKBShared` 中。要么是键盘扩展单独打包，要么此 mod 依赖微信侧内置挂钩承载语音 Widget。请确认你设备上实际启用的键盘扩展是哪个。
- 它能在“扩展里直接联网+录音”依赖 **TrollStore 伪签发 entitlements**（麦克风 / audio 后台 / 网络 / app group）。App Store 版键盘扩展受内存与网络限制，官方部分场景才会“跳转主程序”；此 mod 把整条链路塞进扩展，从而实现免跳转。
